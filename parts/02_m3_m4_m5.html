A hashmap (Python's dict and set) turns a key into a storage position using a hash function, so lookup, insert and delete are O(1) on average. Different keys can land on the same position (a collision), which Python resolves by probing for another free slot. In the worst case with many collisions, operations degrade to O(n), but that is rare.

Keys must be hashable, meaning immutable: strings, numbers and tuples work, but lists do not.

Most hashmap problems follow one of three patterns:

  • Seen before? Remember what you have met so far, so a repeat or a needed partner is found instantly.
  • Counting. How many times does each item appear?
  • Grouping. Put items that share a key into the same bucket.

Given a list of numbers and a target, return the indices of the two numbers that add up to the target. Assume exactly one answer exists.

two_sum([2, 7, 11, 15], 9)   # [0, 1], because 2 + 7 = 9

Do it in two steps, the way you would in the interview: first write the brute force and state its complexity, then improve it with a dictionary.

Brute force: check every pair. Time O(n²), space O(1).

[[py:two_sum_brute]]

Optimized: as you walk the list, ask "have I already seen the number that completes this one?" If yes, you are done.

[[py:two_sum]]

Walkthrough on [2, 7, 11, 15], target 9:

  • i=0, n=2, need 7. Not in seen yet, so store {2: 0}.
  • i=1, n=7, need 2. It is in seen at index 0, so return [0, 1].

Time O(n), space O(n). This is the trade you should say out loud: extra memory for speed. Check need in seen before storing the current number, so a number is never paired with itself.

Write each one:

  1. is_anagram(a, b): do two strings use exactly the same letters with the same counts?
  2. has_duplicate(nums): does any value appear twice?
  3. group_anagrams(words): ["eat","tea","tan","ate","nat","bat"] becomes [["eat","tea","ate"],["tan","nat"],["bat"]].

[[py:hash_basics]]
  • Anagram: two Counters are equal when every letter has the same count. O(n).
  • Duplicate: a set drops repeats, so a shorter set means a duplicate existed. O(n).
  • Group anagrams: words that are anagrams share the same sorted letters, so that sorted string is the dictionary key. If the longest word has length L, this costs O(n · L log L).
  • Top k: most_common(k) is roughly O(n log k). A bucket approach (index = frequency) can reach O(n), which is a nice follow-up to mention.
 A hash function converts the key into an integer, which is mapped to a slot in an underlying array. Lookup computes the same hash and jumps straight to that slot, so on average it takes O(1) time regardless of size. A collision is two different keys mapping to the same slot. Chaining stores a small list of entries in each slot. Open addressing (used by Python's dict) probes for the next free slot. Both stay fast as long as the table is not too full, which is why tables resize as they grow. Keys must be hashable, and a hash must never change. A list is mutable, so its contents (and hash) could change after insertion and the dictionary could never find it again. Use a tuple instead. A dict maps keys to values. A set stores only unique keys with no values. Both give O(1) average membership checks. O(n), if all keys collide into the same place. With a good hash function this is very unlikely, so we quote O(1) average. When you need the data in sorted order (use a sorted list or tree), when memory is very tight, or when the keys have no good hash function.

Return True if a string reads the same forwards and backwards, ignoring case and anything that is not a letter or digit.

is_palindrome("A man, a plan, a canal: Panama")   # True
is_palindrome("race a car")                        # False

Hint: put one pointer at each end and move them towards each other. Try to do it without building a cleaned copy of the string.

[[py:palindrome]]

Skip non-alphanumeric characters on each side, then compare the two characters case-insensitively. Time O(n), space O(1). The simpler version t = "".join(c.lower() for c in s if c.isalnum()); return t == t[::-1] is also fine (O(n) space), and worth mentioning as the quick option.

prices[i] is the price on day i. Buy once, sell later, and return the maximum profit (0 if no profit is possible).

max_profit([7, 1, 5, 3, 6, 4])   # 5  (buy at 1, sell at 6)
max_profit([7, 6, 4, 3, 1])      # 0
[[py:max_profit]]

Walk through the days once, remembering the lowest price seen so far. On each day ask: "if I sold today, having bought at the cheapest earlier day, what would I make?" Keep the best answer. Time O(n), space O(1). The brute force checks every buy/sell pair in O(n²).

Find the largest sum of any contiguous part of a list that may contain negatives.

max_subarray([-2, 1, -3, 4, -1, 2, 1, -5, 4])   # 6  (the part [4, -1, 2, 1])
max_subarray([-3, -1, -2])                        # -1
[[py:kadane]]

At each number you have two choices: extend the running subarray, or start a new one at this number. If the running sum so far is negative, it only hurts, so starting fresh is better. current holds the best sum ending here, and best holds the best seen anywhere. Time O(n), space O(1).

Start with nums[0], not 0, so an all-negative list still returns the correct (negative) answer.

Return the length of the longest stretch of the string with no repeated character.

length_of_longest_substring("abcabcbb")   # 3  ("abc")
length_of_longest_substring("bbbbb")         # 1
length_of_longest_substring("pwwkew")         # 3  ("wke")

Hint: keep a window [start, i] with no repeats. When a repeat appears, slide the left edge past the earlier copy.

[[py:longest_substring]]

The dictionary remembers the last index of each character. When the current character was last seen inside the window (last_seen[ch] >= start), move start just past that earlier copy. The window length is i - start + 1.

The trap: the >= start check. In "abba", when the final a arrives, its old position (0) is already outside the window, so you must not move start backwards. Try it by hand. Time O(n), space O(k) for k distinct characters.

Merge all overlapping intervals.

merge_intervals([[1,3],[8,10],[2,6],[15,18]])   # [[1,6],[8,10],[15,18]]
[[py:merge_intervals]]

Sort by start time. Then each interval either overlaps the last merged one (its start is at or before that one's end, so extend the end) or does not (start a new one). Sorting dominates: O(n log n). This "sort first, then sweep" pattern shows up constantly, for example with meeting rooms or transaction time windows.

Move every 0 to the end of the list in place, keeping the order of the non-zero values.

move_zeroes([0, 1, 0, 3, 12])   # [1, 3, 12, 0, 0]
[[py:move_zeroes]]

Two pointers: read scans every element, and write marks where the next non-zero value belongs. Swapping non-zero values forward pushes zeroes to the back. One pass, O(n) time, O(1) extra space.

A linked list is a chain of nodes. Each node holds a value and a pointer to the next node. Unlike an array, elements are not next to each other in memory.

append walks to the last node: O(n). prepend is O(1). delete keeps a pointer to the node before the one being removed, so it can skip over it with curr.next = curr.next.next. The head is a special case because it has no previous node.

Write each, using ListNode and the helpers above:

  1. reverse_list(head): reverse the list and return the new head.
  2. has_cycle(head): does the list loop back on itself?
  3. middle_node(head): return the middle node (the second of the two middles for even lengths).
  4. merge_two_lists(a, b): merge two sorted lists into one sorted list.

Hint for 2 and 3: use two pointers moving at different speeds.

[[py:ll_algos]]
  • Reverse: for each node, remember the rest, flip its pointer backwards, then step forward. Four lines you should be able to write on demand. O(n) time, O(1) space.
  • Cycle (Floyd's tortoise and hare): slow moves one step, fast two. If there is a loop, fast eventually laps slow and they meet. If there is no loop, fast reaches the end. O(n) time, O(1) space, versus O(n) space for a "visited" set.
  • Middle: when fast reaches the end, slow is halfway, since it moved half as far.
  • Merge: a dummy head node avoids special-casing the first node. Repeatedly attach the smaller front node. When one list runs out, attach the rest of the other. O(n + m).
 Pick an array when you need fast access by index or a compact memory layout. Pick a linked list when you insert and delete a lot at known positions (especially the front) and rarely index. A doubly linked list has a pointer back to the previous node as well. That allows walking in both directions and O(1) deletion of a node you hold, at the cost of more memory per node. After slow and fast meet, reset one pointer to the head. Move both one step at a time. They meet again at the node where the cycle begins. Copy the next node's value into this node, then link past the next node: node.val = node.next.val; node.next = node.next.next. It does not work for the last node. Find the middle with slow and fast pointers, reverse the second half, then compare the two halves node by node. Optionally reverse it back afterwards.
