These are the problems that show up most often in campus coding rounds, grouped by topic. Each has a difficulty tag. Work in order within a topic, and use the 20-minute rule. If you are short on time, do the Priority ones first, since they cover the most common patterns.

Which technique for which problem?

The hardest part of a new problem is choosing the approach. Use the wording of the problem as a clue:

If the problem says...Think about...
find a pair, a complement, a duplicate, or count occurrencesHashmap or set
sorted array, or "find the position"Binary search, or two pointers
contiguous subarray or substringSliding window, or prefix sums
do it in place, or remove or move itemsTwo pointers (a read pointer and a write pointer)
next greater element, matching brackets, nested structureStack
middle, cycle, or n-th from the end of a linked listFast and slow pointers
top k, k-th largest or smallestHeap
level by level, or shortest path with equal costsBFS (queue)
explore everything, or connected regionsDFS (recursion or stack)
count the ways, or best result from a series of choices, with repeated sub-questionsDynamic programming

Arrays

Remove duplicates from a sorted list in place, so each value appears once. Return the number of unique values k. The first k slots must hold the unique values in order. Do not create a new list.

a = [1, 1, 2, 2, 2, 3]
remove_duplicates(a)   # 3, and a[:3] is [1, 2, 3]
[[py:dsa_remove_dups]]

Because the list is sorted, duplicates sit next to each other. read scans every element, and write marks the next free slot for a new unique value. A value is new if it differs from the last value written. Time O(n), space O(1).

A list holds n distinct numbers taken from 0..n, so exactly one number in that range is missing. Find it.

missing_number([3, 0, 1])   # 2

Try to do it in O(n) time and O(1) space. Hint: what should the total of 0..n be?

[[py:dsa_missing]]

The sum of 0..n is n(n+1)/2. Subtract the actual sum and what is left is the missing number. An alternative that avoids any overflow worry in other languages is XOR (see the bits problems below). Time O(n), space O(1).

Find the value that appears more than n/2 times in a list (it always exists). Aim for O(1) extra space.

majority_element([2, 2, 1, 1, 1, 2, 2])   # 2
[[py:dsa_majority]]

This is the Boyer-Moore voting idea. Keep a candidate and a counter. The same value adds 1, a different value subtracts 1, and at zero you pick a new candidate. Since the majority value outnumbers all others combined, it cannot be cancelled out entirely. Time O(n), space O(1). The easy alternative is Counter(nums).most_common(1), which is O(n) space. Mention both.

Return a list where element i is the product of all elements except nums[i]. Do not use division.

product_except_self([1, 2, 3, 4])   # [24, 12, 8, 6]

Hint: the answer for position i is (product of everything to its left) times (product of everything to its right).

[[py:dsa_product]]

The first pass stores, in result[i], the product of everything to the left of i. The second pass, going right to left, multiplies in the product of everything to the right. No division, so zeroes in the input are handled correctly. Time O(n), and O(1) extra space apart from the output list.

Rotate a list to the right by k places, in place.

rotate([1, 2, 3, 4, 5, 6, 7], 3)   # [5, 6, 7, 1, 2, 3, 4]
[[py:dsa_rotate]]

The neat trick is three reversals: reverse the whole list, then reverse the first k, then reverse the rest. Take k %= n first, since rotating by n changes nothing. Time O(n), space O(1). The one-liner nums[:] = nums[-k:] + nums[:-k] is also fine, but it uses O(n) extra space.

A list contains only 0, 1 and 2. Sort it in place in a single pass, without using sort().

sort_colors([2, 0, 2, 1, 1, 0])   # [0, 0, 1, 1, 2, 2]
[[py:dsa_colors]]

Three pointers split the list into regions: everything before low is 0, everything from low to before mid is 1, and everything after high is 2. Inspect nums[mid]: a 0 swaps to the front, a 1 stays, and a 2 swaps to the back. When you swap with high, do not advance mid, because the value swapped in is still unchecked. One pass, O(n) time, O(1) space.

Count the contiguous subarrays whose sum is exactly k. The list may contain negative numbers.

subarray_sum([1, 1, 1], 2)   # 2
subarray_sum([1, 2, 3], 3)   # 2   ([1, 2] and [3])

Hint: with a running (prefix) sum, a subarray ending here sums to k if some earlier prefix equals running - k.

[[py:dsa_subarray_sum]]

Let running be the sum of everything so far. A subarray that ends at the current element and adds up to k exists for every earlier prefix whose sum was running - k, because removing that prefix leaves exactly k. The dictionary counts how many times each prefix sum has occurred. Seeding counts[0] = 1 covers subarrays that start at index 0. Time O(n), space O(n). The brute force checks every pair of start and end in O(n²), and sliding window does not work here because of negative numbers.

Find all unique triplets in a list that add up to 0.

three_sum([-1, 0, 1, 2, -1, -4])   # [[-1, -1, 2], [-1, 0, 1]]
[[py:dsa_three_sum]]

Sort the list, then fix the first number and use two pointers on the rest to find pairs that complete a zero sum: if the total is too small, move lo right, and if too big, move hi left. Skipping repeated values (for the first number and for the second) is what keeps the result unique. Time O(n²), space O(1) besides the output. This is a classic "reduce to two sum" problem, so say that out loud.

Strings and bits

Return the longest prefix shared by every string in a list, or an empty string.

longest_common_prefix(["flower", "flow", "flight"])   # "fl"
longest_common_prefix(["dog", "car"])                 # ""
[[py:dsa_lcp]]

Start with the first word as the prefix. For each other word, chop one letter off the end of the prefix until the word starts with it. Time O(total characters), space O(1). Watch the edge cases: an empty list, and a single word (which is its own prefix).

Write two short functions. reverse_words(" the sky is blue ") should give "blue is sky the", ignoring extra spaces. is_rotation("waterbottle", "erbottlewat") should be True.

[[py:dsa_string_misc]]

split() with no argument splits on any run of whitespace, so the extra spaces vanish. For the rotation trick: every rotation of a appears inside a + a, so check the lengths match, then check b in a + a. Both are O(n).

Three short problems on bits:

  1. Every value in a list appears twice, except one. Find it in O(n) time and O(1) space.
  2. Is n a power of two?
  3. Count the 1-bits in n.

Hint: XOR (^) of a number with itself is 0, and n & (n - 1) clears the lowest 1-bit of n.

[[py:dsa_bits]]
  • Single number: XOR all the values. Pairs cancel each other (x ^ x = 0) and 0 does not change anything, so only the unpaired value remains.
  • Power of two: a power of two in binary has exactly one 1-bit, and n & (n - 1) removes it, leaving 0. Check n > 0 too.
  • Count set bits (Brian Kernighan's method): repeat n &= n - 1, counting how many times before n becomes 0. It loops once per 1-bit.

Stacks and linked lists

For each element, find the next element to its right that is strictly greater. Use -1 when there is none.

next_greater([2, 1, 2, 4, 3])   # [4, 2, 4, -1, -1]

Hint: keep a stack of positions that are still waiting to find something bigger.

[[py:dsa_next_greater]]

This is the monotonic stack pattern. The stack holds indices of values that have not yet found a greater one. When a new value arrives, it is the answer for every waiting index with a smaller value, so pop and fill those in, then push the new index. Each index is pushed and popped at most once, so time is O(n) and space is O(n). The brute force is O(n²). The same pattern solves "daily temperatures" and "stock span".

Use ListNode, from_list and to_list from the linked lists module.

  1. remove_nth_from_end(head, n): remove the n-th node counted from the end, in one pass.
  2. add_two_numbers(a, b): two numbers are stored as linked lists with digits in reverse order ([2,4,3] means 342). Return their sum in the same format.
remove_nth_from_end([1,2,3,4,5], 2)   # [1, 2, 3, 5]
add_two_numbers([2,4,3], [5,6,4])     # [7, 0, 8]   (342 + 465 = 807)
[[py:dsa_ll_more]]
  • Remove n-th from the end: move fast n steps ahead, then move both pointers together until fast reaches the last node. Now slow sits right before the node to delete. A dummy node in front handles removing the head. One pass, O(n) time, O(1) space.
  • Add two numbers: walk both lists together, adding the digits and a carry. divmod(total, 10) gives the carry and the digit at once. The loop continues while either list has nodes or a carry remains, so [9,9] + [1] correctly produces [0,0,1]. Time O(max(n, m)).

Searching and heaps

A sorted list of distinct values was rotated at an unknown point, for example [4, 5, 6, 7, 0, 1, 2]. Find the index of target in O(log n), or return -1.

search_rotated([4, 5, 6, 7, 0, 1, 2], 0)   # 4
search_rotated([4, 5, 6, 7, 0, 1, 2], 3)   # -1

Hint: after you split at the middle, at least one half is always properly sorted.

[[py:dsa_rotated]]

At each step, work out which half is sorted: if nums[lo] <= nums[mid], the left half is sorted. Then ask whether the target lies inside that sorted half's range. If yes, search that half, and if no, search the other half. Every step still discards half the range, so it is O(log n) time and O(1) space. Test with the target being the first element, the last element, the pivot, and a missing value.

Return the k-th largest value in an unsorted list.

kth_largest([3, 2, 1, 5, 6, 4], 2)   # 5
[[py:dsa_kth]]

Keep a min-heap of size k that always holds the k largest values seen so far. Push each number, and if the heap grows past k, pop the smallest. At the end, the root is the k-th largest. Time O(n log k), space O(k). Compare with the simple answer, sorted(nums)[-k], which is O(n log n). The heap version wins when k is small or the data is a stream.

Trees

Use TreeNode, bst_insert and inorder from the trees module to build a tree to test with.

Write three functions:

  1. invert_tree(root): swap the left and right children at every node.
  2. is_valid_bst(root): is this a valid binary search tree?
  3. lowest_common_ancestor(root, p, q): for a BST, the lowest node that has both values p and q beneath it.

Hint for 2: comparing a node only with its direct children is not enough. Each node must fall inside a range set by its ancestors.

[[py:dsa_tree_more]]
  • Invert: recursively invert both subtrees, then swap them. It is a classic quick recursion problem. Time O(n).
  • Validate BST: pass down an allowed range (low, high). Going left, the upper limit becomes the current value. Going right, the lower limit becomes the current value. The common mistake is checking only parent against child, which wrongly accepts a tree where a deep node breaks an ancestor's rule. An alternative is to check that inorder traversal is strictly increasing.
  • LCA in a BST: if both values are smaller than the current node, go left. If both are larger, go right. Otherwise, the paths split here, so this is the answer. Time O(height), space O(1).

Dynamic programming

Dynamic programming (DP) applies when a problem breaks into overlapping subproblems and the best answer is built from the best answers to smaller ones. Use this recipe every time:

  1. State: what does dp[i] mean, in words?
  2. Recurrence: how does dp[i] follow from smaller states?
  3. Base case: the smallest answers you know directly.
  4. Order: fill the table so the pieces you need already exist.
  5. Answer: which cell holds the result? Then see if you can shrink the memory.

You can climb 1 or 2 steps at a time. How many distinct ways are there to reach step n?

climb_stairs(1) = 1,  climb_stairs(2) = 2,  climb_stairs(3) = 3,  climb_stairs(5) = 8

Hint: to reach step n, you came from step n-1 or step n-2.

[[py:dsa_stairs]]

State: ways(n) is the number of ways to reach step n. Recurrence: ways(n) = ways(n-1) + ways(n-2), which is the Fibonacci sequence. Because only the last two values are needed, two variables replace the whole table: O(n) time and O(1) space. The plain recursion without memory would be O(2n), which is exactly why DP exists.

Houses in a row hold money, and you cannot rob two adjacent houses. What is the most you can take?

rob([1, 2, 3, 1])      # 4   (houses 1 and 3)
rob([2, 7, 9, 3, 1])   # 12  (houses 1, 3 and 5)
[[py:dsa_rob]]

At each house you choose: take it (then you must have skipped the previous one, so add to the "skip" total) or skip it (keep the best of the previous two choices). The two running variables hold those totals. The tuple assignment evaluates the right side first using the old values, which is what makes the update correct. Time O(n), space O(1).

Given coin values and a target amount, return the fewest coins that make the amount, or -1 if it is impossible. You have unlimited coins of each value.

coin_change([1, 2, 5], 11)   # 3   (5 + 5 + 1)
coin_change([2], 3)          # -1
coin_change([1, 3, 4], 6)    # 2   (3 + 3, not 4 + 1 + 1)

Watch out: always picking the biggest coin (greedy) fails on the third example.

[[py:dsa_coin]]

State: dp[a] is the fewest coins needed to make amount a. Recurrence: try every coin c that fits, and take dp[a - c] + 1 if it improves the best. Base case: dp[0] = 0. Unreachable amounts stay at infinity, which becomes -1 at the end. Time O(amount × number of coins), space O(amount). The third example shows why greedy is wrong and DP is needed: greedy would choose 4 first and end up with 3 coins, while the best is 2.

Return the length of the longest subsequence (characters in order, not necessarily next to each other) that two strings share.

lcs("abcde", "ace")   # 3   ("ace")
[[py:dsa_lcs]]

State: dp[i][j] is the LCS length of the first i characters of a and the first j characters of b. If the two current characters match, extend the best answer without them (dp[i-1][j-1] + 1). Otherwise take the better of dropping a character from either string. Time and space O(n × m). A subsequence need not be contiguous, and that is the difference from a "substring" problem.

Graphs

A graph is a set of nodes connected by edges. The usual representation in interviews is an adjacency list: a dictionary that maps each node to the list of its neighbours. It uses O(V + E) space, unlike an adjacency matrix, which uses O(V²).

For graph = {"A": ["B", "C"], "B": ["D"], "C": ["D"], "D": []}, write:

  1. bfs(graph, start), returning the nodes in the order they are visited, level by level
  2. dfs(graph, node), returning the visit order going as deep as possible first
bfs(graph, "A")   # ["A", "B", "C", "D"]
dfs(graph, "A")   # ["A", "B", "D", "C"]
[[py:dsa_graph]]

BFS uses a queue, so nodes closest to the start are processed first. That makes it the tool for shortest paths when every edge costs the same. DFS uses recursion (or an explicit stack) and goes deep before backtracking. Both need a seen set, or a graph with cycles would loop forever. Both run in O(V + E) time.

A grid of "1" (land) and "0" (water) is given as a list of lists. Count the islands. An island is land connected up, down, left or right.

11000
11000
00100
00011      ->  3 islands
[[py:dsa_islands]]

Scan every cell. When you find land, you have found a new island, so count it, and then use DFS to flood-fill (sink) the entire island to water, so it is never counted again. Time O(rows × cols), and space O(rows × cols) in the worst case for the recursion. Mention that you modified the input grid, and that you could use a separate seen set if the input must stay unchanged. Very deep recursion can hit Python's recursion limit on huge grids, and BFS with a queue avoids that.

 Recursion solves a problem by calling itself on a smaller input, and is often shorter and clearer for trees and graphs. Iteration uses loops, and avoids the call-stack cost and the risk of a stack overflow. Every recursion needs a base case, or it never stops. A technique for problems with overlapping subproblems and optimal substructure. Instead of recomputing the same sub-answers, you store them. Memoization does this top-down (recursion plus a cache), while tabulation does it bottom-up (filling a table). Greedy takes the best-looking choice at each step and never reconsiders. It is fast but only correct for some problems. DP considers all the choices through stored sub-answers, so it is always correct when the problem has the right structure. Coin change with coins 1, 3, 4 is the standard example where greedy fails. A list stores only the edges that exist, giving O(V + E) space and fast iteration over neighbours, so it is best for sparse graphs. A matrix uses O(V²) space but checks whether an edge exists in O(1), which suits dense graphs. The average cost per operation over a long sequence, even if a single operation is occasionally expensive. Appending to a Python list is amortized O(1): it is normally cheap, and the occasional resize is spread out over many appends. The fastest, typical and slowest running time for an input of size n. Quicksort is O(n log n) on average but O(n²) in the worst case. Interviewers usually want the worst case unless you say otherwise. The algorithm changes the input directly and uses only O(1) extra space, rather than building a new copy. Many array problems ask for it, and it usually means using two pointers or swaps. A hash table gives O(1) average lookup, but its keys are unordered. A balanced BST gives O(log n) operations, but keeps keys in sorted order, so range queries and "next larger key" are easy. Then code and test. Saying this process aloud is worth as much as the answer.
