Big-O in one minute

Big-O describes how the work grows as the input size n grows. You state it in every coding answer.

O(n²)quadratica loop inside a loop over the same input

The toolkit

Read this block slowly and type it into a Python file. The comments show what each line returns.

[[py:py_toolkit]]

Write top_two_words(text) that returns the two most common words as a list of (word, count) pairs, ignoring upper or lower case.

top_two_words("a b A c b a")   # [('a', 3), ('b', 2)]

Hint: split the text, then look at collections.Counter.

[[py:wordfreq]]

lower() makes "A" and "a" count as the same word, split() breaks the text on whitespace, and Counter(...).most_common(2) returns the top two. Time is O(n) to count, plus a small sort of the distinct words. Space is O(n).

Edge cases to mention: empty text (returns an empty list), and punctuation like "hello," which would count separately unless you strip it.

Plain recursion without the cache recomputes the same values again and again, taking O(2n) time. With the cache it is O(n). The iterative version is O(n) time and O(1) space, so it is usually the best answer.

 A list is mutable (you can change it after creation) and a tuple is immutable. Tuples are slightly faster and, being immutable and hashable, can be used as dictionary keys. Use a tuple for fixed data such as coordinates. Mutable objects can change in place (list, dict, set). Immutable ones cannot (int, float, str, tuple, frozenset). "Changing" an immutable value really creates a new object. == checks whether two values are equal. is checks whether two names point to the very same object in memory. Use is mainly for None checks (x is None). The default list is created once, when the function is defined, and shared by every call. Appending to it in one call changes what later calls see. The fix is def f(x=None): and then if x is None: x = [] inside. A shallow copy (list.copy(), copy.copy) copies the outer container but shares the inner objects. A deep copy (copy.deepcopy) copies everything recursively. It matters for nested lists: changing an inner list through a shallow copy changes the original too. A function that uses yield to produce values one at a time instead of building a whole list. It saves memory for big or endless sequences, because only one value exists at a time. A stack is last in, first out (LIFO), like a pile of plates. A queue is first in, first out (FIFO), like a ticket counter line. Interviewers ask you to build both because it shows you understand how data structures work underneath.

In Python, a plain list works well as a stack because append() and pop() at the end are O(1). It is a poor queue, because pop(0) shifts every element and costs O(n). For a queue use collections.deque, where append() and popleft() are both O(1).

Write a Queue class with enqueue(x), dequeue(), peek(), is_empty() and size(). Then answer in words:

  1. Why deque and not a list?
  2. What is the time complexity of each method?
  3. How does your dequeue() behave on an empty queue, and why did you choose that?
[[py:queue]]

1. Why deque. list.pop(0) is O(n) because every remaining element shifts left. deque.popleft() is O(1).

2. Complexity. All five methods are O(1).

3. Empty queue. Raising IndexError makes the bug visible immediately. Returning None is also acceptable, but then callers must remember to check, and a real None stored in the queue becomes ambiguous. Say which you chose and give the reason, since that is what gets scored.

Given a string containing only ()[]{}, return True if every bracket is closed by the correct type in the correct order.

is_valid("()[]{}")   # True
is_valid("{[()]}")   # True
is_valid("(]")       # False
is_valid("(((")      # False

Hint: what is the last opening bracket you have seen that is still unclosed?

[[py:valid_parens]]

Idea: push every opening bracket. When a closing bracket arrives, it must match the most recent unclosed opening one, which is the top of the stack.

Walkthrough for {[()]}: push {, push [, push (. Then ) pops (, a match. ] pops [, a match. } pops {, a match. The stack is empty, so the answer is True.

Edge cases: a closing bracket first ("]", stack empty, so False), and leftover openers at the end ("(((", so the final return not stack gives False). Time O(n), space O(n).

Design a stack that supports push, pop, top and get_min, where get_min returns the smallest element in O(1) time.

Hint: what extra information can you store with each element so the minimum survives pops?

[[py:min_stack]]

Each entry stores the value and the minimum of everything at or below it. When you pop, the previous entry still knows its own minimum, so nothing needs recomputing. Every operation is O(1), and space is O(n).

A classic follow-up. Build a queue using only two stacks (Python lists, using only append and pop at the end).

Hint: pouring one stack into another reverses the order.

[[py:queue_two_stacks]]

Push new items onto the _in stack. When you need to dequeue and _out is empty, pour everything from _in into _out. That reverses the order, so the oldest item is now on top. Each element moves at most once, so dequeue is amortized O(1): occasionally slow, but O(1) on average over many operations.
